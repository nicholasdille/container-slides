# Data Visualization for Traces

!!! goal "Goal"

    - Follow a request across multiple services

!!! tipp "Resources"

    - Use the [official documentation of TraceQL](https://grafana.com/docs/tempo/latest/traceql/)
    - The traces in this exercise are generated by the demo application `podinfo` which you deployed in the [chapter about data collection](../030_data/exercises.md#task-5-deploy-demo-application)

## Introduction: TraceQL

Traces are stored in **Grafana Tempo** and queried using **TraceQL**.

A trace represents a single request as it travels through the system. It consists of multiple **spans** - one per operation, for example an HTTP request to `podinfo` or the call to the backend. Spans carry attributes like the service name, the HTTP method and the duration.

A TraceQL query consists of one or more **conditions** wrapped in curly braces:

```traceql
{ .service.name="podinfo-frontend" && duration > 10ms }
```

Conditions are matched against individual spans. Multiple expressions can be combined into spansets using `&&` and `||`. Structural operators like `>>` (descendant) and `<<` (ancestor) relate spans to each other - this is what allows you to follow a request across services.

## Preparation: Generate traces

TraceQL only finds traces that were actually sent to Tempo. Create the port forwarding for `podinfo` and generate some traffic. See [task 6 in the chapter about data collection](../030_data/exercises.md#task-6-create-a-port-forwarding).

Execute the following commands to trigger traces across both the frontend and the backend:

```shell
curl -sX POST -d foo http://localhost:9898/api/echo
curl -s http://localhost:9898/delay/1
curl -s http://localhost:9898/status/500
```

## Task 1: Display a first trace

1. Go to Explore in Grafana
1. Switch the data source to `Tempo`
1. Make sure that the query language is set to `TraceQL` (right hand side above the query)
1. Display all traces from the frontend of the demo application

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" }
    ```

## Task 2: Filter by duration

The command `curl -s http://localhost:9898/delay/1` triggered a slow request. Filter for traces of the frontend which took more than one second.

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" && duration > 1s }
    ```

## Task 3: Filter for errors

The command `curl -s http://localhost:9898/status/500` triggered a failing request. Filter for failed spans of the frontend.

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" && status = error }
    ```

## Task 4: Follow a request across services

Display only spans that belong to both services. This is the query from the [chapter about data collection](../030_data/exercises.md#task-6-working-with-traces).

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" } && { .service.name="podinfo-backend" }
    ```

The result contains two spans: One for the frontend and one for the backend.

## Task 5: Use the structural operator

The query from task 4 finds traces containing both services but the two spansets are independent. The structural operator `>>` finds spans which are descendants of another span. This reflects the call hierarchy: The frontend called the backend.

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" } >> { .service.name="podinfo-backend" }
    ```

    The result only contains the backend spans which are children of a frontend span. Using `<<` instead would return the frontend spans which are ancestors of a backend span.

## Task 6: Filter by attributes

Display spans of the frontend for requests to the path `/api/echo`.

??? help "Solution (Click on the arrow if you are stuck)"
    ```
    { .service.name="podinfo-frontend" && .http.route="/api/echo" }
    ```

    Depending on the instrumentation, the attribute is called `.http.route` or `.url.path`. Open a single trace and inspect the attributes of a span to find out which ones are available. Autocomplete in the query editor lists them, too.
